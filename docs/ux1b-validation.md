# ผลตรวจ UX1b — ขายและชำระเงิน

วันที่ 26 ตุลาคม 2026: ปรับหน้าขายตาม [brief](ux1b-sales-brief.md) ภายใน white/navy เดิม ต่อจาก UX1a ผล finish review ไม่พบข้อบกพร่องสำคัญที่ขวางการส่งมอบในขอบเขต UX1b ยังไม่ใช่การปิด UX1 ทั้งหมดหรือ Android acceptance

## ขอบเขตที่ส่งมอบ

- มือถือแสดงเมนูเต็มแถว ชื่อยาวขึ้นบรรทัดได้ แสดงจำนวนชิ้นและยอดรวม พร้อม “ดูรายการ” ที่ย้าย focus ไปหัวข้อรายการในบิล และ “ไปชำระเงิน”
- หน้าชำระแสดงยอดก่อน ส่วนลดเปิดเพิ่มผ่าน details เมื่อต้องใช้ เลือกบัญชีที่รับเงินจริงเอง มี “ใช้ยอดที่เหลือ” และ “รับพอดี” ช่วยกรอก พร้อมแสดงเงินทอนและยอดจัดสรรขาด/เกิน
- ตรวจร้าน วัน รายการ ยอด และเงินทอนใน review ก่อนยืนยัน ผลสำเร็จใช้ข้อมูลจาก server; ย้าย focus ตามขั้นชำระ/review/กลับแก้ไข/สำเร็จ
- รักษา pricing, validation, API, idempotency key/payload, identity binding และ explicit retry เดิม ไม่เปลี่ยน default account หรือถือว่าการตัดสินใจเรื่องบัญชีที่ยังรอยืนยันได้รับอนุมัติแล้ว

## กฎภาพที่พบใน build

อ่าน `apps/web/src/pos/PosWorkspace.tsx`, `pos/workflows.css`, `pos/pos.css`, `index.css` เทียบกับ [PRODUCT.md](../apps/web/PRODUCT.md) และ brief บันทึกเฉพาะสิ่งที่ใช้จริง:

1. สี navy (`#1e3a5f`) บนขาว ข้อความหลัก (`#172b4d`) ข้อความรอง (`#475569`) เส้นแบ่ง (`#cbd5e1`); พื้นอ่อน (`#f4f7fa`) แยกบิลจอใหญ่ และ (`#edf2f8`) เน้นเงินทอน
2. Tahoma, Noto Sans Thai, sans-serif ตาม stack เดิม; body 18px/1.65 หัวข้อขั้น 24px ยอดชำระ 28px เงินทอน 22px น้ำหนัก 700 ยอดในแถบรวม 24px ลดเป็น 22px บนมือถือ ตัวเลขใช้ tabular-nums
3. **กฎเมนูอ่านเต็ม:** ไม่เกิน 640px เมนูเป็นหนึ่งคอลัมน์ ปุ่มสูงอย่างน้อย 72px ชื่อขึ้นบรรทัดได้ ปุ่ม/ช่องกรอกทั่วไปอย่างน้อย 48px; จอใหญ่ตั้งแต่ 960px วางเมนูคู่กับบิล
4. **กฎยอดก่อนกรอก:** ยอดอยู่ก่อนส่วนลดและบัญชี เงินทอนมีพื้นอ่อนและตัวเข้ม การกระทำหลักบนมือถือเต็มความกว้าง; ระยะหลัก 8/16/24px เส้นแบ่งและพื้นสีช่วยแยกส่วนโดยไม่มีเงาใหม่
5. **กฎตรวจแล้วค่อยบันทึก:** เลือกเมนู → ชำระ → review → ผลจาก server มีหัวข้อรับ focus ในแต่ละขั้นและวง focus ตามระบบเดิม (`3px`, offset `4px`)

เป็น ordinary refinement ไม่เปลี่ยน visual world จึงไม่สร้าง `DESIGN.md` หรือ `.impeccable/design.json` และไม่ยก composition เฉพาะหน้านี้เป็นกฎทั้งระบบ

## Checks และข้อจำกัด

ผลตรวจ final source ของงาน UX1b: root `npm test` ผ่าน 42 tests ใน 17 files; root typecheck, lint และ build ผ่าน Impeccable detector คืน `[]` ไม่มีการแก้ UI หลัง checks ชุดนี้ เอกสารนี้รวบรวมผลที่ตรวจแล้ว ไม่ได้รัน checks หรือถ่ายภาพซ้ำเพื่อแก้เอกสาร

ไม่มีการเปลี่ยน DB และไม่ได้รัน PostgreSQL integration ซ้ำใน slice นี้ Browser mock และ fixture retry ไม่พิสูจน์ atomicity, rollback หรือ concurrency ของ backend

ยังไม่ได้ตรวจ Android เครื่องจริง คีย์บอร์ดมือถือ screen reader ขนาดตัวอักษรใหญ่ หรือให้แม่ยอมรับการใช้งาน; ไม่อ้างว่าครบ acceptance ทุกสถานะ session/สิทธิ์/เครือข่าย หรือพร้อม production

ความคลาดเคลื่อนที่ไม่ยกเป็นกฎใหม่: shell เดิมมีข้อความรอง 16px และฟอนต์ระบบใน stack ไม่ยกเป็น display-face rule สำหรับหน้าต่อไป งานนี้รักษา incumbent และไม่ขยายไปแก้ทั้งระบบ
