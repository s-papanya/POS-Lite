# UX1c — ผลตรวจเข้าใช้และเลือกร้าน

วันที่ 26 ตุลาคม 2026; ปรับภายในระบบขาว/navy เดิมตาม [brief](ux1c-access-brief.md) และ [PRODUCT.md](../apps/web/PRODUCT.md) เป็น ordinary refinement ไม่สร้าง `DESIGN.md` หรือ `.impeccable/design.json`

## สิ่งที่เปลี่ยน

- ฟอร์มเข้าสู่ระบบและรายการร้านมีความกว้างพอดีบนจอใหญ่ มือถือเรียงหนึ่งคอลัมน์ เห็นชื่อร้าน สิทธิ์ และ “เข้าร้าน” ในแถวเดียวกัน
- ย้าย focus ไปหัวข้อเมื่อเปลี่ยนหน้าเข้าใช้/เลือกร้าน และไปกลุ่มตรวจรายการเมื่อขอเปลี่ยนร้านหรือออกจากระบบ ระหว่างนั้นปิดการทำงานหน้าร้าน; “อยู่ต่อ” คืน focus ให้ปุ่มเดิม
- การเปลี่ยนร้านที่มีรายการค้างแยก “เก็บไว้แล้วเปลี่ยนร้าน”, “ทิ้งแล้วเปลี่ยนร้าน” และ “อยู่ต่อ” โดยปุ่มทิ้งเป็นการกระทำรอง
- รักษา password input, autocomplete, คำขอ auth, CSRF/cookie, pending guards และ sessionStorage ที่ผูกกับ identity เดิม ไม่เปลี่ยน backend หรือความหมายสิทธิ์

## กฎภาพที่พบใน build

อ่าน `apps/web/src/StoreAccess.tsx`, `pos/workflows.css`, `pos/pos.css` และ `index.css` บันทึกเฉพาะสิ่งที่ใช้จริง:

1. **กฎสีเดิม:** พื้นขาว ตัวอักษรหลัก (`#172b4d`) navy (`#1e3a5f`) สำหรับการกระทำ ข้อความรอง (`#475569`) และเส้นแบ่ง (`#cbd5e1`); แถวร้านเมื่อ hover ใช้พื้นอ่อน (`#edf2f8`)
2. **กฎลำดับตัวอักษร:** Tahoma, Noto Sans Thai, sans-serif; body 18px/1.65 หัวข้อเข้าใช้ 30px ลดเป็น 28px ที่ความกว้างไม่เกิน 640px ชื่อร้านและหัวข้อตรวจรายการ 22px สิทธิ์ร้าน 16px และคำ “เข้าร้าน” 18px
3. **กฎฟอร์มพอดีจอ:** ส่วนเข้าใช้กว้างไม่เกิน 560px อยู่กึ่งกลาง ระยะบน 32px ลดเป็น 24px บนมือถือ; ช่องกรอกและปุ่มคงพื้นที่กดอย่างน้อย 48px ตามระบบเดิม
4. **กฎแถวร้านอ่านเต็ม:** รายการร้านใช้เส้นแบ่ง ไม่มีกรอบการ์ดแยก ชื่อขึ้นบรรทัดได้ ชื่อและสิทธิ์อยู่ซ้าย การเข้าร้านอยู่ขวา ระยะในแถวบนล่าง 20px; ไม่เพิ่มภาพหรือเงาใหม่
5. **กฎตัดสินใจก่อนออก:** กลุ่มตรวจรายการแสดงในหน้า ใช้พื้นแจ้งเตือนเดิม ปุ่มเรียงลงและเต็มความกว้างบนมือถือ; หัวข้อ/กลุ่มรับ focus และ “อยู่ต่อ” คืน focus จุดเริ่ม ตามวง focus เดิม (`3px`, offset `4px`)

กฎเหล่านี้อธิบาย artifact ของ slice นี้ ไม่ยกระดับ composition เฉพาะหน้าเป็นระบบภาพใหม่

## หลักฐาน browser

ใช้ local preview ใน `apps/web/test/preview-server.mjs` และบัญชี/ข้อมูลจำลอง ไม่มี credentials จริง หลักฐานต่อไปนี้รวบรวมจากการตรวจ UX1c ในงานนี้ ไม่ใช่การพิสูจน์ auth หรือสิทธิ์ของ backend จริง

| เรื่อง | ผลที่ตรวจได้ |
|---|---|
| เข้าสู่ระบบผิดและลองใหม่ | fixture ตอบ 401 แสดงข้อความผิดพลาดและเก็บค่าในฟอร์ม; ผู้ใช้กดเข้าสู่ระบบอีกครั้งแล้วสำเร็จ |
| เลือกร้านและเริ่มรายการ | เข้าร้านก๋วยเตี๋ยว เพิ่ม 1 รายการ ยอด 35 บาท |
| เปลี่ยนร้าน/อยู่ต่อ | focus เข้ากลุ่มตรวจรายการ งานหน้าร้าน disabled; “อยู่ต่อ” คืน focus ที่ “เปลี่ยนร้าน” |
| เก็บรายการ | เก็บแล้วเปลี่ยนร้าน กลับเข้าร้านเดิมพบ 1 รายการ |
| ทิ้งรายการ | ทิ้งแล้วเปลี่ยนร้าน กลับเข้าร้านเดิมพบ 0 รายการ |
| ออกจากระบบ | ยืนยันออกจากระบบแล้วกลับฟอร์มพร้อมข้อความออกจากระบบ |
| ไม่มีร้าน | แสดงข้อความให้ติดต่อเจ้าของร้าน |
| ขนาดหน้าจอ | ตรวจภาพมือถือ 360px และ desktop 1440px; หน้าเข้าใช้/เลือกร้านที่ viewport 320px มี scroll width 320px |

ภาพภายในเครื่อง 8 ภาพอยู่ที่ `.impeccable/review/ux1c/`: `stores-mobile.png`, `stores-desktop.png`, `stores-320.png`, `login-mobile.png`, `login-desktop.png`, `login-320.png`, `leave-mobile.png`, `no-stores-mobile.png` ไฟล์ถูก ignore และไม่เป็น deliverable ใน Git

Finish reviewer ให้ disposition `ship` ไม่มี material fixes จากหลักฐานชุดนี้

## Checks และข้อจำกัด

ผลตรวจ final source ของ UX1c: root `npm test` ผ่าน 42 tests ใน 17 files; root typecheck, lint และ build ผ่าน Impeccable detector คืน `[]`; skill validator ผ่าน และสำเนา skill canonical/`.claude` ตรงกัน เอกสารนี้รวบรวมผลที่ตรวจแล้ว ไม่รัน checks หรือถ่ายภาพซ้ำเพื่อแก้เอกสาร

ไม่ได้ตรวจ Android เครื่องจริง คีย์บอร์ดมือถือ screen reader หรือการยอมรับจากแม่; browser fixture ไม่พิสูจน์ auth, authorization, CSRF/cookie ของระบบจริง หรือ acceptance ทุกสถานะ และไม่ยืนยันความพร้อม production

ความคลาดเคลื่อนที่ไม่ยกเป็นกฎใหม่หรือแก้ในงานนี้: ฟอนต์ระบบใน stack และข้อความรอง 16px เป็น incumbent ไม่กำหนดให้เป็น display-face rule หรือขยายไปแก้ทั้งระบบ
